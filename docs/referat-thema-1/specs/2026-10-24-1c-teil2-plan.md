# 1C Teil 2 Implementation Plan

> **Hinweis zur Entstehung:** Dieser Plan steuert die Ausführung durch Claude Code (siehe [Design Abschnitt 9](2026-10-24-1c-teil2-design.md#9-ki-nutzung)). Schritte im Checkbox-Format.

**Goal:** Close the open parts of 1C without private inference: an end-to-end PostgreSQL suite up to a local test runtime (E1–E9), a reproducible local measurement series (M1–M5), the counter-variant V1 with a decision, corrections to part 1, and one consolidated PR.

**Architecture:**

- **Test runtime:** an in-process HTTP server on 127.0.0.1 acts as llama-server.
- **What runs for real:** the router, queue, context builder, open-weight client and HTTP.
- **What is mocked:** only the host-token check.
- **Shared fixture helper:** used by the existing hash suite and the new E2E and measurement suites.
- **Measurements:** run as an opt-in vitest file that writes raw JSON.

**Tech Stack:** Vitest, Prisma/PostgreSQL 16, Redis 7.4, node:http, Node 24.18.0 (`mise exec node@24.18.0 --`).

**Spec:** [2026-10-24-1c-teil2-design.md](2026-10-24-1c-teil2-design.md) (pre-registered in commit `9170e80b`).

## Global Constraints

- **No production code changes.** Mutation probes are local only and reverted with `git checkout -- <file>`; record each with its diff, red run, green run and the commit SHA it ran against.
- **H/G/K:** exactly as in the design. Any change is noted in the protocol with a reason.
- **Commits:**
  - Conventional Commits.
  - No AI attribution trailers. AI use is disclosed in the documents instead.
  - Never `git add` local services, secrets or `.superpowers/`.
- **Test titles:**
  - No referat IDs (E1, T5.x) in the titles. The protocol maps IDs to titles.
  - PG suites: English `describe` ending in `(PostgreSQL + Redis)`, German `it`.
- **Local services:** Podman `arsnova-1c-pg` / `arsnova-1c-redis`:
  - `DATABASE_URL=postgresql://arsnova_user:…@localhost:5432/arsnova_v3_migration?schema=public`
  - `REDIS_URL=redis://localhost:6379`
- **Synthetic secrets only:** the runtime token is a fixed 32+ character test string.

## Review Focus

1. The test runtime must not hide client behaviour. It answers through real HTTP, and the assertions read the **raw** received body, never a re-serialised object.
2. E7 and E8 must change the database **during** the runtime call (inside the handler, before responding), not before the request.
3. Measurement wrappers must call the real functions unchanged. Timing uses `performance.now()`; warm-up runs are discarded.
4. Queue and client module state between tests: use `resetQaSummaryQueueForTests()` and `resetOpenWeightLlmClientForTests()`, close the server, and unstub the env.
5. CI runtime: the 200-participant fixture must stay within a reasonable CI time. If it does not, reduce it for E only and record why.
